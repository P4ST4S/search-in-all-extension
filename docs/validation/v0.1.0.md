# Validation v0.1.0 et v0.1.1

Vérification initiale du 24 octobre 2026 sur macOS 27.0.1 (26A434), Node.js 23.5.0. Correctifs de fermeture et de focus livrés en v0.1.1 le 25 octobre 2026.

À la demande de l’utilisateur, les essais d’interface ont été réalisés dans le **navigateur interne**, avec les vrais scripts UI et des données fictives. Aucun profil Brave n’a été utilisé ou modifié. La version installée de Brave relevée est **156.1.98.60**, mais cette version n’a pas été utilisée pour les essais.

## Vérifications exécutées

| Contrôle | Résultat |
| --- | --- |
| `npm test` | 36 tests réussis, zéro échec après les corrections de fermeture et de focus |
| `npm run check` | Syntaxe, version, permissions, ressources et absence de surfaces supplémentaires : OK |
| `git diff --check` | Aucun problème relevé |
| `npm run preview` | Serveur local sur 127.0.0.1:4173 ; aperçu consulté dans le navigateur interne |

Les tests Node couvrent la distinction adresse/recherche, les caractères spéciaux, les schémas refusés, tous les dossiers de favoris, le classement et ses limites, le complément fantôme, la sélection clavier et les réponses périmées. Les tests du contrôleur couvrent les messages et expéditeurs invalides, une API absente ou en erreur, la relecture des destinations, la bascule entre fenêtres, les onglets/favoris disparus, l’échec du moteur, les activations concurrentes et la reprise avec un contrôleur neuf.

Les API sont simulées dans ces tests : ils ne prouvent pas leur compatibilité effective avec Brave.

## Revue ciblée de l’extension

- MV3, CSP locale, aucune permission d’hôte, ressource exposée aux sites, substitution du nouvel onglet ou messagerie externe.
- Rendu par `textContent` et création d’éléments ; aucun HTML provenant des titres, adresses ou requêtes.
- Aucun `eval`, code distant, appel réseau, télémétrie, journalisation de requêtes réelles ou stockage persistant dans l’extension.
- Injection dans le monde isolé ; racine fermée sur les sites ; événements synthétiques refusés pour les actions.
- Opérations privilégiées regroupées dans le contrôleur ; expéditeur et contexte vérifiés ; destinations relues depuis les API et limitées à HTTP(S) pour les créations d’onglets.
- Aucune écriture dans les favoris. En cas d’échec de recherche, seul l’onglet vide créé par l’extension, encore intact, peut être supprimé.

## Ajustement après retour utilisateur

L’utilisateur a confirmé que la fenêtre supplémentaire avait été observée sur une page interne et a demandé de conserver le secours sur ces pages uniquement. La palette était aussi jugée trop basse.

- La superposition est désormais ancrée à `clamp(24px, 18dvh, 160px)` depuis le haut, au lieu d’aligner le champ sur le milieu de la page. La hauteur de liste suit l’espace disponible.
- Le contrôleur relit l’onglet réel à l’activation. Seules les pages internes peuvent créer la fenêtre de secours ; une erreur d’injection sur une page web déclenche le badge d’erreur sans ouvrir de fenêtre.
- Deux tests de régression ont échoué avant le correctif puis réussi après : absence de fenêtre sur échec d’injection web et relecture de la page malgré des métadonnées de bouton périmées. Suite complète : 30 tests réussis.
- Rendu remonté inspecté dans le navigateur interne, avec le même exemple `eco`, sur la fenêtre habituelle et en 360 × 480 ; la liste et le pied du panneau restent visibles. Le viewport temporaire a été réinitialisé. Le fonctionnement réel de l’extension dans Brave reste à vérifier par l’agent ; le signalement utilisateur est distingué de ces essais.

## v0.1.1 — Correctifs de fermeture et de focus

- Fermeture sur `visibilitychange` lorsque `document.hidden` est vrai, et sur `pagehide`. Pas de demande explicite de restitution du focus à la page quittée ; les rappels différés sont annulés et les écouteurs retirés.
- Champ avec `autofocus`, délégation de focus dans le Shadow DOM, recontrôle à la frame suivante et au retour du focus de la fenêtre. La protection de focus laisse le bouton de fermeture accessible.
- Les touches de la palette sont interceptées en capture sur `window`, avant les raccourcis de niveau `document`, sans annuler l’édition native pour Retour arrière, Suppr, sélection ou IME. Aucun changement de permissions.
- Six tests de régression supplémentaires utilisent un double DOM et exécutent le vrai script de la palette : masquage/navigation, nettoyage, retour tardif du focus, reprise de focus par la page, navigation au bouton et blocage des raccourcis hôtes. Ces événements simulés ne constituent pas une validation native de Brave.

Dans le navigateur interne, la fixture `?editor=chat&focus-race=1` ajoute un éditeur contenteditable et des gestionnaires de page en capture qui effacent le focus du Shadow DOM et annulent les touches de suppression. Le blocage de Retour arrière a été reproduit avec la protection de clavier placée après ces gestionnaires. Après correction, avec racine ouverte puis fermée :

- `abcde`, Retour arrière, deux déplacements à gauche puis Suppr produit `abd`, avec le focus dans la palette et le brouillon du chat intact.
- Cmd+A puis Retour arrière efface toute la saisie. Tab et Maj+Tab gardent l’accès au bouton de fermeture et au champ.
- Échap restitue le focus à l’éditeur en mode injecté. L’édition du chat fictif fonctionne ensuite ; aucun écouteur de la palette ne bloque ses touches. Aucune erreur de console relevée.

L’ouverture d’un second onglet par l’outil du navigateur interne n’a pas masqué le premier document (`document.hidden` restait faux) : ce parcours ne prouve donc pas la fermeture native au changement d’onglet. Celle-ci est couverte par les événements simulés en test et reste à vérifier dans Brave. Le site ChatGPT réel n’a pas été utilisé.
